# ProcQuit 模块划分

## 问题与方案

原 `ProcQuit.cpp` 为 3161 行，入口初始化、进程列表、任务栏交互、快捷键配置、浮窗及鼠标热键共用文件级状态。新增界面需求容易影响无关功能。

本次按职责拆成独立编译单元，优先迁移原实现，不改变配置格式、快捷键语义和窗口行为。模块状态保持私有，通过明确的生命周期接口通信，不建立共享全局状态头文件。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| ProcQuit | DPI、COM、公共控件初始化和主消息循环 |
| MainWindow | 主窗口、托盘、设置/关于窗口、进程列表及批量操作协调 |
| ShortcutConfig | 快捷键数据模型、键名解析及配置读取 |
| ShortcutPanel | 非激活浮窗、布局、绘制、滚动、提示、拖拽、快捷键编辑和发送 |
| MouseTrigger | 全局热键注册、配置更新回滚、按键释放检测、定时器及鼠标输入 |
| WindowControls | 主窗口与快捷键浮窗共用的按钮创建、悬停与绘制 |
| ProcessExit | 原有进程退出能力和诊断日志 |

主窗口显式传入实例及状态栏句柄。面板和鼠标模块不访问主窗口的文件级变量；所有窗口状态仍由 UI 线程管理，进程退出工作线程保持原有消息通知方式。

## 行为与性能约束

- 浮窗继续使用非激活样式，避免输入发送目标被自身抢占。
- 保留批量窗口定位、禁止重绘期间更新、tooltip 复用及异步删除/重排消息，避免新增闪烁或重复布局。
- 保留鼠标热键 10ms 检测、5 秒超时及更新失败的原配置恢复逻辑。
- 主窗口销毁时注销热键并取消定时器，等待退出线程，再销毁浮窗。
- 不引入状态副本、额外线程或轮询；本次优化重点为依赖隔离和增量编译可维护性，不宣称运行速度提升。

## 后续需求规则

1. 新增功能先确认归属，再修改拥有该职责的模块；禁止重新将浮窗、解析或输入逻辑堆进入口文件。
2. 公共接口只暴露操作和必要的数据类型，不暴露内部 HWND 容器或可写全局状态。
3. 快捷键解析、格式兼容归配置模块；视觉交互归面板；全局热键与定时器归鼠标模块。
4. 进程扫描和 UIAutomation 若继续增长，应从 MainWindow 提取独立服务；不要为了减少行数建立循环依赖。
5. 原注释保持不变，新增日志使用英文，代码文件使用 UTF-8 BOM。
6. 构建中间结果、测试输出和临时脚本放在项目 cache 目录；构建检查使用显式 OutDir/IntDir 覆盖，避免污染源码目录。

## 回归清单与已知范围

- 检查主窗口搜索、排序、选择同步、批量退出及强制终止。
- 检查托盘显示/退出，关闭隐藏与最小化行为。
- 检查快捷键窗口的发送、录制、增删、清空、恢复、重排、滚动及悬停提示。
- 检查全局热键冲突、配置保存失败回滚、按键释放超时和退出清理。
- 保持重复分类段、顺序及原配置编码兼容。配置保存已有的同目录替换临时文件策略不在本次结构调整范围，后续单独评估原子替换与 cache 限制。

本次不修改进程退出策略、配置内容或现有功能；编译检查不能替代上述人工桌面交互验证。

- 迁移检查确认原有整行注释和函数均保留，代码文件 UTF-8 BOM 检查及 git diff --check 通过。
- 入口由 3161 行缩减到 57 行；主窗口、配置、浮窗、鼠标触发和共用控件分别编译。
